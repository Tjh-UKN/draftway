# 北极星工作区接入协议草案

版本 0.2，面向 Windows 桌面。本文同时包含当前接口和后续协议约定。Windows WebView2、三类执行器适配、后台 Review 观察、材料读取和 MCP 地图工具已实现；实际验证与外部限制见 [组件交付](component-delivery.md)、[后台提醒](background-runtime.md)、[工作区工具](workspace-tools.md)。声明式第三方 Manifest 的其他可选能力不因本文示例自动启用。

北极星以事件为主线，把思考、执行、结果和知识放在同一工作区。Review 看板、思维导图、Obsidian 和浏览器保留各自合适的操作界面；北极星管理它们的入口、会话、后台任务与结果提醒。

应用命令和笔记面板的插件使用独立的 `northstar-plugin.json` 声明，安装、执行和宿主 API 见 [插件协议](plugins.md)。

## 产品对象

| 对象 | 含义 | 保存的关系 |
| --- | --- | --- |
| 事件 Event | 用户准备推进或验收的事 | 关联思维节点、执行任务和产物 |
| 工作区 Workspace | 一组相关工作现场 | 包含多个视图实例和任务绑定 |
| 视图实例 SurfaceInstance | 某个工具正在使用的界面 | 工具、文档或页面、浏览器配置、视图状态 |
| Agent 会话 Session | 一段由宿主管理的 Agent 对话 | Agent 类型、所属工作区和节点、来源会话标识、记录与草稿 |
| 执行任务 Run | 一次真实的 AI 或后台执行 | 来源任务标识、状态、所属事件和产物 |
| 产物 Artifact | 报告、笔记、文件或修改结果 | 来源任务、关联事件、打开位置 |

一个工具可以出现在多个工作区；同一工作区也可打开多个同类视图。工具安装、连接配置和视图实例分别保存。事件数据独立于思维图布局，节点通过事件标识建立关联。

工作区可以随用户新增。新增业务通过适配器注册；主界面依赖能力声明，不按 PR、闪卡、认知报告等业务名称分支。

## 接入协议

协议标识为 `northstar.integration/1`。宿主与适配器协商主版本，未知能力保留为不可用。适配器只声明实际实现的能力。

注册适配器、授权连接和调用动作分别处理。动作按标识、参数结构与工作区授权校验；外部页面的权限独立于宿主，凭据通过系统凭据存储引用。第三方工具的内容不能自行扩大适配器权限。

| 契约 | 最小内容 | 宿主行为 |
| --- | --- | --- |
| Manifest | 工具标识、版本、视图类型、能力、动作列表 | 注册入口，按能力显示操作 |
| Surface | 打开、聚焦、关闭视图；可选捕获与恢复会话 | 用户直接操作工具原界面 |
| Actions | 动作标识、参数结构、执行主体与权限 | 把人或 AI 的调用交给适配器 |
| Runs | 来源任务标识、修订号、执行状态与结果引用 | 在后台跟踪任务并生成提醒 |
| Artifacts | 产物标识、类型、关联事件与定位信息 | 从提醒回到对应结果 |

通信方式由适配器选择。第一版 Review 适配器使用现有 HTTP API；进程内组件和本机应用可走宿主接口或本机 IPC。AI 工具调用可兼容 MCP，并在双方声明支持时复用 MCP Tasks 扩展；工作区、视图和产物关系由本协议补充。[MCP Tasks 规范](https://tasks.extensions.modelcontextprotocol.io/specification/2026-07-28/tasks)

### 注册示例

以下是 Review 适配器的目标声明；保存声明文件本身不会启用这些能力。

```json
{
  "protocol": "northstar.integration/1",
  "id": "local.pr-review",
  "version": "1.0.0",
  "name": "PR 检视看板",
  "surfaces": [
    {
      "id": "dashboard",
      "kind": "webview",
      "entry": "http://127.0.0.1:8765/"
    }
  ],
  "capabilities": [
    "surface.open",
    "surface.focus",
    "runs.observe"
  ],
  "actions": []
}
```

`surface.capture`、`surface.restore`、`runs.start`、`runs.cancel` 和 `artifact.reveal` 都是可选能力。宿主在适配器实现并通过检查后才开放对应操作。观察已有任务不自动取得启动、取消或发布权限。

### Agent 会话与执行

节点与会话是同一工作区内的两类独立对象。新建会话选择 Agent，默认仅归属当前工作区；关联已有节点是可选操作，不自动创建地图节点。节点可以没有会话，也可以关联多个会话；会话也可关联多个已有节点。

地图是固定的“工作区”页签，会话在其旁边以页签打开；选中会话显示聊天区域，返回“工作区”恢复地图位置与选中节点。会话页签通过 `sessionId` 引用会话；每个工作区保存打开顺序、当前页签和最近使用顺序。顶部“会话记录（N）”查找并重新打开已有会话，不提供重复的创建入口。

真实适配器另存来源会话标识或会话文件、运行位置、工作目录和连接状态，使用各 Agent 支持的恢复方式。不同 Agent 的来源历史不假定格式相同，不把任意网站聊天链接当作受管会话。

会话可包含多次执行 `Run`。宿主管理记录和归属，适配器提供实际支持的创建、发送、恢复和停止能力；不支持的能力不启用。关闭会话页签只关闭视图，停止执行是显式操作；会话历史、当前执行和任务验收分别管理。

执行结果可声明地图更新：创建值得保留的产物节点、修改指定节点内容、追加节点进展。目标必须属于会话工作区；保存来源会话和执行标识，重复结果不得重复应用。普通对话不自动成为节点，用户也可主动将结果放到地图。

浏览器预览使用模拟 Agent；Windows 版使用真实执行器，保存来源会话标识并托管进程。已实测的后端及认证限制见组件交付记录。

### 视图状态保存

视图状态以 `workspaceId + instanceId` 为键，保存 `integrationId`、视图类型、资源引用和适配器可恢复的 `viewState`。Agent 对话的身份由独立 `Session` 保存，不用标签标识替代。网页登录态归属浏览器配置；凭据通过受保护的引用关联。

例如，导图保存选中节点、展开分支、位置和缩放；网页保存适配器支持恢复的页面与视图位置；Obsidian 保存库和笔记位置。只有适配器声明支持的状态才承诺恢复，未保存的编辑缓冲区需要对应工具配合。

工作区另存布局和 `activeInstanceId`。日常点击常驻入口直接恢复该工作区最后使用的视图与焦点；缩略图总览用于寻找和整理工作区。

关闭视图、停止任务和删除业务数据是三个独立动作。切换工作区只改变前台现场；后台任务由执行服务管理。

### 后台任务状态

执行状态为 `queued`、`running`、`needs_input`、`succeeded`、`failed`、`cancelled`。连接另有 `connected`、`disconnected`、`unknown` 状态；连接中断时保留最后任务状态并标明失联。

适配器发送完整任务快照，宿主按 `connectionId + sourceRunId + attempt` 识别任务，按递增的 `revision` 接受更新。`eventId` 用于重传去重。任务重试建立新的 attempt，已结束的 attempt 不回退为运行中。

```json
{
  "protocol": "northstar.integration/1",
  "eventId": "evt-review-42-7",
  "connectionId": "review-local",
  "sourceRunId": "review-task-42",
  "attempt": 1,
  "revision": 7,
  "state": "succeeded",
  "occurredAt": "2026-11-14T01:30:00Z",
  "artifacts": [
    {
      "id": "report-42",
      "kind": "report",
      "resourceRef": "round-example.json"
    }
  ]
}
```

例中的标识和时间用于说明字段，不表示真实任务已经执行。宿主根据已授权的绑定，把来源任务关联到工作区、事件和视图实例。

执行结果、结果是否已读、事件是否验收分别保存。一次 AI 执行成功后，事件进入待查看或待验收阶段；满足用户定义的完成条件后，再更新事件完成状态。

### 通知和后台宿主

Windows 后台宿主管理连接、任务快照、通知记录和结果定位。界面切换或收起不会销毁监控；第一版采用托盘常驻。完全退出宿主会停止其拥有的本机执行器；独立 Review 服务不由北极星管理，可继续运行，北极星退出后不再实时提醒。

宿主在同一事务内保存新的任务状态和待发送提醒。提醒投递失败可重试；重复快照不重复建立提醒。首次接入先记录历史基线；重连后补读实际可获取的变化，超出来源历史保留范围时标明状态缺口。

默认提醒执行结束、失败或需要用户输入；普通进度变化只更新工作区标记。后台完成不会抢走当前焦点。点击提醒按保存的绑定恢复工作区和结果位置；缺少精确定位能力时明确进入结果列表。

一个工作区同时存在多个任务时，展示运行数量、待处理数量和未读结果数量；整体状态由任务集合推导，不能让最后一个任务覆盖其他任务的状态。

## 各工具的接入方式

| 工具 | 用户操作界面 | 后台状态来源 | 第一版边界 |
| --- | --- | --- | --- |
| Review 看板 | 原页面作为受管 WebView 的顶层页面 | 状态和报告 API；后续任务事件接口 | 先观察真实任务，结果定位能力单独适配 |
| 思维导图 | 北极星内置组件 | 节点关联的事件与任务 | 保持节点标识、事件标识和布局分离 |
| Obsidian | 定位原生 Obsidian 窗口和笔记 | 桥接插件或执行任务适配器 | URI 先支持打开和聚焦，双向状态另接插件 |
| 浏览器 | 受管 WebView；完整浏览器可接原生窗口或浏览器桥接器 | 页面业务 API 或执行器报告 | 用户操作、AI 代操作分别声明能力 |

网页承载采用顶层 WebView。当前看板的 `X-Frame-Options: DENY` 和 `frame-ancestors 'none'` 保留。Windows 独立预览现采用 Tauri 2.12.1 的 `unstable` 子 WebView API，并通过原生运行探针验证实际看板加载、历史保留、尺寸同步和访客命令拒绝。主 WebView 拥有宿主权限，网页访客没有；完整的 Windows 鼠标交互回归尚未完成。[Tauri WebView 文档](https://v2.tauri.app/reference/javascript/api/namespacewebview/)

Obsidian 官方 URI 支持打开库、笔记和定位窗口。插件 API 支持订阅应用和文件事件；这些能力可以作为桥接基础。原生应用的界面承载与网页承载使用不同适配器。[Obsidian URI](https://help.obsidian.md/Extending+Obsidian/Obsidian+URI)、[Obsidian 插件事件](https://docs.obsidian.md/Plugins/Events)

### Review 看板的现有依据

本地服务提供 `GET /api/status`、`GET /api/reports` 和 `GET /api/reports/{file}`。`runtime.active_prs` 表示当前排队或执行中的 PR；报告包含 `round_status`、失败计数与来源报告文件。

适配器以报告的最终状态判断结果，不能把 `runtime.running = false` 直接解释为检视成功。首次连接不为历史报告批量发提醒。报告列表最多返回 50 条；可靠补读和精确的单任务通知需要补充稳定任务标识与可续读的状态来源。

现有服务有开始检视和全局暂停接口。全局暂停不等同于单任务取消；第一版不声明 `runs.cancel`。检视意见发布继续属于看板自己的用户操作，观察适配器不自动发布。

本地实现依据：`claude-pr-review-automation/src/pr_review_bot/dashboard.py` 中的 `status`、`reports` 与 HTTP 路由；`pipeline.py` 中的报告终态生成；`state.py` 中的任务记录。

## 与 Orca 的关系

Orca 已经具备工作区、浏览器、Agent 状态钩子和结果提醒；其主要组织模型围绕代码仓库、worktree、Agent 会话与交付变化。增加这些能力本身不能构成北极星的独有差异。[Orca Worktrees](https://orca.dev/docs/model/worktrees)、[Orca Browser](https://orca.dev/docs/browser/overview)、[Orca Notifications](https://orca.dev/docs/notifications)

北极星的产品选择是以事件为主线：思维节点形成事件，事件派生执行任务，报告和笔记回到事件，复盘再进入知识记录。一个工作区可以同时关联代码检视、学习笔记、研究资料和个人事务。这个差异需要通过共享事件模型、产物追踪和跨工具工作流实现。

## 第一条交付链

第一阶段先用明确标注的模拟适配器验证：从节点创建会话、在内部视图操作、切换工作区、接收结果标记、点击通知返回原会话。第二阶段先接通一个真实 Agent 的创建、消息、恢复与停止，再接入现有 Review 看板的状态、报告和结果定位；之后增加 Obsidian 笔记的打开与桥接能力。

验收覆盖：切换工作区后继续监控；服务断线不报完成；首次接入不报历史完成；重复事件不重复提醒；失败报告不标成功；多个工作区使用同一连接时不重复创建来源任务；重启恢复快照后补读；结果定位不跨事件或工作区。
