# 备份与恢复

从「业务组件 → 数据与设置」创建完整备份或选择 ZIP 恢复。工作区会先等待布局与会话草稿保存，再创建备份。

备份包含业务 SQLite、地图与布局、模板和接入配置、通知与 AI 更新日志、会话数据库、附件、Draftway 默认工作目录中的文件，以及 Pi 来源会话文件。`node_modules`、`.venv`、`__pycache__` 等依赖缓存不复制。自选的外部项目目录和 Obsidian 库仍由原目录管理，需要另行备份；网页登录态、执行器认证和外部 Codex／Claude 来源历史不包含在 ZIP 中。

备份写入临时文件，完成结构和容量检查后再成为可见的 ZIP。数据库使用 SQLite 备份接口读取；压缩期间释放主库锁。每份备份最多 10000 个文件、解压后总计 2 GB，单文件最多 512 MB；超出时明确报错，不发布无法恢复的备份。恢复与正在压缩的备份发生交叠时，旧备份会中止。

恢复前必须先结束正在执行或等待输入的会话。宿主暂停写入、关闭闲置执行器，创建当前状态的保护备份，再恢复数据库和文件；成功后自动重新打开应用。普通错误会自动回滚两份数据库与文件目录。意外退出留下恢复标记时，下次启动尝试从原保护备份回滚；恢复失败不会自动清空数据。

在不同目录恢复时，Draftway 管理的工作目录、材料路径和 Pi 来源文件会重定位。Pi 会话头也会更新，确保实际工具使用新工作目录。外部项目路径保持原引用，缺失时需要重新选择目录。备份中未结束的执行在恢复后标为中断。

旧版备份不包含新工作区和会话组件时，恢复它的业务数据，同时保留当前新组件的数据。若旧备份有会话入口却不含日志，会提示缺失，不会伪装为仍在创建。

## 已验证

- 新目录恢复会话数据库、默认目录文件和完整 JSONL 行；排除依赖缓存。
- 正常错误回滚两份数据库和文件目录；未完成恢复按保护备份恢复。
- 旧版备份兼容、路径穿越、可执行扩展和 Windows 重名路径拒绝。
- Pi 实际恢复多轮上下文，并通过相对文件读取验证使用重定位后的目录。
- Windows 实际执行恢复命令、自动重开并读到备份中的记录；GUI 程序的 MCP 在 Windows 与 WSL 管道均可使用。

历史与文件恢复检查使用独立测试目录。已安装原版的数据目录没有被这些检查替换。原生鼠标、拖放与系统通知横幅仍需单独的 GUI 验收。
